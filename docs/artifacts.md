# Artifacts and accepted state

Anchor Bench keeps generated bytes under `outputs/` and human-managed YAML
under `configs/`. A path locates an artifact; its manifest and hashes establish
its identity.

## Profiles are not runs

Phase profiles are editable recipes:

```text
configs/robots/<robot>/
  sysid/profiles/*.yaml
  train/profiles/*.yaml
  benchmark/profiles/*.yaml
  deploy/profiles/*.yaml
```

Changing a profile affects only future resolutions. It does not mutate an
existing run, accepted state, or frozen deployment.

SysID and training runs are content addressed:

```text
outputs/<phase>/<robot>/<profile>/seed-<seed>/<run-input-sha256>/
```

The semantic input hash includes the resolved recipe, selected upstream state,
dataset and asset fingerprints, source fingerprint, dependencies, seed, and
optional replicate label. Formatting, timestamps, logging, `--dry-run`, and an
output root do not create a different candidate.

## SysID runs

```text
outputs/sysid/<robot>/<profile>/seed-<seed>/<run-input-sha256>/
  resolved_config.yaml
  parent_state.yaml
  fitted_patch.yaml
  sysid_state.yaml
  metrics.yaml
  manifest.yaml
```

`parent_state.yaml` is the complete state used to start the run.
`fitted_patch.yaml` contains only optimized parameter/joint cells.
`sysid_state.yaml` is the authenticated complete candidate:

```text
candidate state = parent state + fitted patch
```

A completed candidate may initialize another SysID run, train a network, or be
benchmarked without promotion. `promote sysid` applies the sparse fitted patch
to the current accepted state; it does not replace unrelated accepted cells.

## Training runs

```text
outputs/train/<robot>/<profile>/seed-<seed>/<run-input-sha256>/
  resolved_config.yaml
  sysid_state.yaml
  checkpoints/best.pt
  stats.json
  network.pt
  manifest.yaml
```

`network.pt` is the deployable TorchScript archive. It embeds `metadata.json`
using neural metadata schema v3, including:

- ordered physical mappings and per-mapping tensor dimensions;
- feature names, domains, components, flattening, and normalization;
- target semantics (`torque` or `torque_residual`);
- recurrent shape, control timestep, and previous-torque behavior;
- frozen residual PD/friction values where required;
- dynamic-bias derivation when used;
- per-output effort limits from the training-time robot asset;
- profile, resolved-config, SysID-state, asset, and source hashes.

The archive is self-contained for benchmark and deployment. Those phases do not
need the copied `sysid_state.yaml`. Training promotion references `network.pt`
in place; it never copies weights into `configs/`.

## Benchmark evidence

Benchmark evaluates one exact SysID or training run:

```text
<output-root>/<robot>/<source-phase>/<benchmark-profile>/
  <source-manifest-sha256>/<benchmark-input-sha256>/
    metrics.yaml
    trajectories/<motion>/real.csv
    trajectories/<motion>/simulated.csv
    manifest.yaml
```

The checked-in profiles currently use `outputs/sim2real_benchmark` as their
output root. An alternate `--output-root` preserves the same layout and semantic
identity. Evidence names the exact source run, source input hash, and source
manifest hash. It is optional during promotion and is never an automatic
acceptance gate.

## Accepted and frozen YAML

These files are state, not generated artifact copies:

```text
configs/robots/<robot>/sysid/default.yaml   # accepted physical parameter cells
configs/robots/<robot>/train/default.yaml   # accepted neural model catalog
configs/robots/<robot>/deploy/default.yaml  # frozen runtime composition
```

`sysid/default.yaml` and `train/default.yaml` are revisioned by explicit
promotion. A new training catalog starts with `models: {}`. The deployment file
does not exist until the first successful `promote deploy`; afterward it remains
unchanged until another deployment promotion.

Accepted training entries and frozen deployment entries contain repository-
relative output paths and hashes. Keep every referenced run. There is no
automatic artifact cleanup.

## Completion and no-op rules

`manifest.yaml` is written last. A completed manifest records every generated
file and raw byte hash plus the resolved semantic input. Repeating an identical
request:

1. acquires the same identity lock;
2. validates the existing manifest and all recorded bytes; and
3. returns a successful no-op if they match.

An incomplete, corrupt, or identity-mismatched final directory is a hard error.
Anchor Bench does not overwrite it or offer a force mode.

## What belongs in git

Commit robot identity, phase profiles, accepted YAML, asset manifests, docs, and
small synthetic fixtures. Do not commit:

- measured datasets or parquet caches;
- neural weights and checkpoints;
- generated SysID or benchmark runs;
- plots, FMUs, or private/large robot assets;
- third-party source checkouts.

Use `third_party/` for ignored local binary artifacts and optional vendor
checkouts. Use `ANCHOR_BENCH_ASSET_DIR` for runtime assets that should not live in
the repository.
